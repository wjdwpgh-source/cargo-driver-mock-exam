## 0. 문서 리비전 관리

### 0.1 리비전 규칙
- 파일명: `개발계획서_v[주버전].[부버전].PRD`
- 로드맵 단계별 계획을 반영할 때마다 **부버전을 1씩 올려** 새 파일을 만든다. (v1.9 다음은 v1.10, v1.11 … — 주버전 v2.0은 승인·큰 방향 변경 때만 사용) (v1.0 = 2단계 요구사항, v1.1 = 3단계 설계, … v1.6 = 8단계 운영)
- 개발 스프린트 결과로 설계가 바뀐 경우에도 부버전 +0.1로 반영한다.
- 승인 후 범위·방향이 크게 바뀌면 **주버전 +1.0** (v2.0)
- 이전 버전 파일은 삭제하지 않고 보관한다.

## 1. 제품 개요

### 1.1 제품 정의
| 항목 | 내용 |
|---|---|
| 제품명 | 화물운송종사자격 모의시험 (가칭) |
| 형태 | 공개용 정적 웹 프로그램 (GitHub Pages) |
| 대상 | 화물운송종사자격시험 응시 예정자 누구나 |
| 핵심 가치 | 가입 없이 바로 실전 모의시험 → 해설 학습 → 오답 복습 → 성적 관리 |
| 비용 | 사용자·운영자 모두 무료 (서버 없음) |

### 1.2 목표 및 성공 지표
| 구분 | 목표 | 측정 방법 |
|---|---|---|
| 학습 효과 | 실전 모의시험을 끝까지 풀고 해설·오답 복습까지 이어지게 한다 | 테스트 사용자 대상 확인 |
| 문제 품질 | 공개 문제의 정답 오류 0건 유지 | GitHub Issues 오류 신고 처리 이력 |
| 문제 풀 | 1차 공개 시 verified 400문항 | 데이터 검증 스크립트 결과 |
| 사용성 | 휴대폰에서 시험 1회를 막힘 없이 완료 | 6단계 테스트 체크리스트 |
| 성능 | 첫 화면 3초 이내 표시(일반 LTE 기준) | 브라우저 개발자도구 측정 |

## 3. 사용자 및 사용 시나리오

### 3.1 사용자 유형
| 유형 | 특징 | 주요 요구 |
|---|---|---|
| 일반 응시자 | 휴대폰으로 틈틈이 학습 | 빠른 접속, 큰 글씨, 이어 풀기 |
| PC 학습자 | 집·사무실 PC에서 실전처럼 연습 | 실전 타이머, 번호판, 상세 해설 |
| 공용 기기 사용자 | 가족·동료가 한 PC를 같이 사용 | 닉네임별 기록 분리 |
| 문제 관리자(운영자) | 저장소 관리자 | 엑셀로 문제 작성 → 변환 → 반영 |

### 3.2 핵심 시나리오
1. **첫 방문**: 접속 → 닉네임 입력 → 대시보드 → "실전 시작" → 80문항 풀이 → 제출 → 결과·해설 확인 → 틀린 문제 자동으로 오답노트 등록
2. **복습**: 대시보드 "복습할 오답 N문제" → 범위·문항 수 선택 → 즉시 해설 모드로 풀이 → 연속 2회 맞힌 문제 졸업
3. **기기 이동**: PC에서 백업 파일 내보내기 → 휴대폰에서 불러오기
4. **다시 시작**: 내 기록 → 초기화 범위 선택 → 백업 권장 안내 → 확인 → 삭제
5. **오류 신고**: 해설 화면 "오류 신고" → 문제 ID가 채워진 GitHub Issue 작성 화면 열림

## 7. 설계 (3단계)

### 7.1 전체 구조
```
index.html
 ├─ app.js            (화면 전환·라우팅: #/start, #/home, #/exam ...)
 ├─ store.js          (브라우저 저장소 읽기·쓰기, 마이그레이션)
 ├─ questions.js      (문제 JSON 불러오기, 상태 필터)
 ├─ exam.js           (출제·타이머·채점)
 ├─ review.js         (오답노트·복습·졸업 규칙)
 ├─ backup.js         (내보내기·불러오기)
 └─ ui/               (화면별 컴포넌트, 차트 – SVG 직접 구현, v1.11)
```
- 프레임워크 없이 순수 JavaScript로 작성하고 빌드 과정 없이 배포한다. **(v1.7 변경)** ES 모듈 대신 일반 스크립트(`<script src>`)와 전역 이름공간 `CDME`를 사용한다. `index.html`을 파일로 직접 열어도 기본 기능이 동작하게 하기 위함이며, 로컬 확인은 `실행.bat`(간이 서버)로 한다. 화면이 복잡해지면 경량 프레임워크(Preact 등) 도입을 검토한다.
- 화면 전환은 주소 해시(`#/...`) 방식으로 처리해 GitHub Pages에서 새로고침해도 깨지지 않게 한다.
- 오프라인 대응(NFR-04)을 위해 Service Worker로 화면 파일과 문제 데이터를 캐시한다.

### 7.3 사용자 기록 저장 구조
- 저장소: **(v1.7 변경)** localStorage를 기본으로 하고, 사용할 수 없으면(시크릿 모드·차단) 메모리에 임시 저장하며 경고를 표시한다. 기록 용량이 작아(100회 약 0.5MB) localStorage로 충분하며, 저장 함수를 분리해 두어 필요 시 IndexedDB로 교체할 수 있다.
- 손상된 기록은 `cdme_broken_시각` 키로 보관 후 새로 시작하고, 더 새로운 `schemaVersion`의 기록이 있으면 덮어쓰지 않도록 저장을 중지한다.
- 최상위 키: `cdme` (cargo-driver-mock-exam)

```json
{
  "schemaVersion": 1,
  "activeProfileId": "uuid",
  "profiles": [ { "id": "uuid", "name": "화물왕", "createdAt": "ISO 일시" } ],
  "data": {
    "uuid": {
      "exams": [
        { "id": "uuid", "startedAt": "", "finishedAt": "", "durationSec": 3720,
          "score": 72.5, "correct": 58, "passed": true,
          "bySubject": { "LAW": {"correct": 18, "total": 25} },
          "answers": [ { "qid": "LAW-0001", "qver": 1, "choice": 2, "correct": true } ] }
      ],
      "wrongNotes": {
        "LAW-0001": { "subject": "LAW", "question_version": 1, "wrong_count": 2, "streak": 0,
                      "last_choice": 3, "first_wrong_at": "", "last_wrong_at": "",
                      "added_by": "auto", "state": "active", "sample": false }
      },
      "reviewSessions": [
        { "id": "uuid", "at": "", "scope": "subject:LAW", "mode": "instant",
          "total": 20, "correct": 14, "mastered": ["LAW-0003"] }
      ],
      "inProgress": null
    }
  }
}
```
- (v1.12) 복습 진행 상태는 `reviewInProgress`(문항별 보기 순서 `perm`, 원래 번호 기준 답안, 문항별 결과, 남은 시간)에 저장한다. 복습 답안은 답할 때마다 오답노트에 바로 반영하며, 복습 세션 기록에는 `answered`, `wrongIds`, `quit`(중도 종료 여부)를 추가한다. 오답노트 항목에는 `mastered_at`, `last_review_at`을 기록한다.
- `inProgress`: 진행 중 시험(문제 목록·버전, 답안, 현재 문항, **남은 시간 `remainingMs`**, 알림 표시 여부, 샘플 여부)을 답 선택·이동 때, 5초마다, 창을 닫을 때 저장 → FR-208 이어 풀기. (v1.8: 마감 시각 대신 남은 시간을 저장해 닫은 동안 시간 정지)
- 응시 기록(`exams`)에는 `sample`(샘플 문제 여부), `timedOut`(시간 종료 자동 제출 여부), `total`(문항 수)을 함께 저장한다. 통계는 현재 모드(실제/샘플)의 기록만 사용한다. (v1.8)
- 오답노트 항목에는 `sample`(샘플 문제 여부)을 함께 저장해 실제/샘플 모드를 구분하고, 수동으로 담은 문제는 `added_by: manual`, `wrong_count: 0`, `added_at`(담은 일시)으로 저장한다. 시험 기록에는 `noteReg`(새로 등록·다시 틀림 수)를 남긴다. (v1.10)
- (v1.13) 백업 파일 형식: `{ "app": "cdme", "kind": "backup", "schemaVersion": 1, "exportedAt": ISO, "profiles": [ { "name", "createdAt", "data": { "exams", "wrongNotes", "reviewSessions" } } ] }`. 불러올 때 `schemaVersion`이 프로그램보다 높으면 거부한다.
- (v1.17) `inProgress`·`reviewInProgress`에 문항별 힌트 사용 여부 `hints`(true/false 배열)를 저장한다(이전에 시작한 시험은 처음 힌트를 볼 때 만든다). 응시 기록의 `answers[]`에는 힌트를 본 문항에 `hint: true`, 기록 전체에 `hintCount`를 남기며, 복습 세션 기록에도 `hintCount`를 남긴다.
- 저장 예상 용량: 실전 1회 약 5KB → 100회 약 0.5MB로 브라우저 한도 내.

### 7.4 핵심 로직

**(1) 실전 출제 (FR-201, 209, 211)**
1. 과목별로 `status = verified` 문제를 모은다.
2. 최근 2회 응시에 나온 문제를 뒤로 미룬 뒤 무작위로 섞는다 (Fisher–Yates).
3. 앞에서부터 규정 수만큼 뽑는다. 부족하면 최근 출제 문제로 채우고, 그래도 부족하면 시작을 막는다.
4. 실전에서는 보기 순서를 섞지 않는다(해설·법령 표기와 일치시키기 위함).

**(2) 채점 (FR-210, FR-212, FR-301) – v1.9 변경**
- 문항별 채점: 답을 고르는 즉시 정오를 판정해 보여 주고, 그 답을 고정한다
- 최종 점수 = 정답 수 × (100 ÷ 총 문항 수), 소수 둘째 자리 반올림
- 합격 = 점수 ≥ `pass_score`
- 시험 종료: 모든 문항을 풀고 "결과 보기"를 누르거나, 시간이 끝나면 종료
- 시간 종료 시 안 푼 문항은 오답 처리

**(3) 오답 등록 (FR-601~603)**
```
제출 → 각 오답·미응답 qid에 대해
  없으면 → 새로 등록 (wrong_count=1, streak=0, state=active, added_by=auto)
  있으면 → wrong_count+1, last_wrong_at 갱신, streak=0, state=active
```

**(4) 복습 채점 (FR-705~706)**
- 화면 표시용 보기 순서 `perm`(예: [3,1,4,2])을 문항마다 만들고, 사용자가 고른 화면 위치를 `perm`으로 원래 번호로 바꿔 채점·저장한다.
- 정답: `streak`+1 → `mastery_streak` 도달 시 `state=mastered`
- 오답: `streak`=0, `wrong_count`+1, `last_choice` 갱신

**힌트 (v1.17 추가, FR-312)**
- 버튼은 보기 아래에 두고 "힌트를 봐도 점수는 그대로이고, 결과에 '힌트 사용'으로 표시됩니다"를 함께 안내한다. 누르면 버튼 자리에 노란 힌트 상자가 열리고 초점이 이동한다. 답을 고르면 힌트 상자는 닫히고 해설에 '💡 힌트 사용' 표시가 붙는다.
- 힌트 글이 없는 문제: "준비된 힌트 글이 없어 틀린 보기 하나(N번)를 지웠습니다" 안내, 지운 보기는 흐리게·취소선·'힌트로 지움' 표시, 클릭·숫자키 선택 불가. 복습에서는 섞인 보기 순서 기준 번호로 안내한다.
- 한 번 본 힌트는 다른 문항에 갔다 오거나 새로고침해도 계속 보인다.

**검수 미리보기 모드 (v1.16 추가)**
- verified 문제가 부족할 때, 초안(draft)·1차 검수(reviewed)를 포함해 과목별 문항이 시험 1회 분량 이상이면 대시보드에 '검수 전 실제 문제로 미리보기'를 표시한다.
- 켜면 폐기되지 않은 실제 문제를 모두 출제 대상으로 하고, 문제마다 '검수 전 · 문제번호'를 표시하며 상단에 정답·해설 오류 가능성을 안내한다.
- 미리보기 시험·복습 기록은 `sample: true, kind: "draft"`로 저장해 실제 성적과 분리하고, 이어 풀기·결과 보기 때 자동으로 미리보기 모드로 맞춘다. 설정 키 `cdme_sample` 값: `1`(샘플) / `draft`(미리보기).

**공개 모드 (v1.21 추가)**
- `data/config.json`의 `"dev_modes": false`이면 공개 사이트에서 검수 미리보기·샘플 모드 버튼과 안내를 모두 숨긴다. 문제가 부족할 때 시작 불가 창에는 "문제를 검수하고 있습니다"만 안내한다.
- 예전에 미리보기·샘플 모드를 켜 둔 기기는 다음 접속 때 실제 모드로 자동으로 돌아간다(그때의 기록은 실제 성적과 분리된 채 보관).
- 운영자는 주소 뒤에 `?dev=1`을 붙여 열면 그 창을 닫을 때까지 미리보기·샘플 모드를 쓸 수 있다(예: `https://wjdwpgh-source.github.io/cargo-driver-mock-exam/?dev=1`).

**개발 확인용 샘플 문제 모드 (v1.8 추가)**
- 실제 문제(verified)가 부족한 동안 화면을 확인할 수 있도록 `data/samples/`의 가짜 문제(지문에 정답 표시)로 동작하는 모드를 둔다.
- 대시보드에서 켜고 끄며, 설정은 기기별(`cdme_sample`)로 저장한다. 켜져 있으면 모든 화면 상단에 표시한다.
- 샘플 응시 기록은 실제 응시 통계와 섞이지 않게 분리한다. 공개(7단계) 전에는 샘플 모드 노출 여부를 다시 결정한다.
