## 4. 발견·수정한 문제

| # | 발견 | 수정 |
|---|---|---|
| 1 | (접근성) 대시보드·결과·기록의 표가 좁은 화면에서 가로로 밀리는데 키보드로 스크롤할 수 없음 | 표 영역에 키보드 초점·이름(`tabindex`, `role=region`)과 초점 테두리 추가 |

| 4 | (접근성) 3번 수정 뒤 그래프 전체가 '그림'으로 표시되어 안의 조작 영역과 충돌 | 그래프 전체를 '묶음(group)'으로 변경 |
| 5 | (저장) 저장 공간이 부족하면 시험 중에는 아무 안내가 없고 다른 화면으로 가야 보임 | 시험 중 저장 실패 시 즉시 한 번 알림 |

| 독립 재풀이 (정답을 숨긴 400문항을 별도 AI 검토자 2명이 다시 풂) | **정답 일치 400/400**, 확신 낮음·지적 3건 (LAW-0010 수리 통지 기한, LAW-0026 시험 실시 횟수 – 근거 원문 확인 필요 / SAFE-0098 핸들 위치 표현 차이) |

> 주의: AI 재풀이는 같은 계열 모델이 작성·검토했기 때문에 같은 착각을 공유할 수 있습니다. 정답 일치는 '명백한 실수가 적다'는 뜻일 뿐, 법령 원문 대조(verified)를 대신하지 않습니다. 계획대로 사람이 과목별 표본 40문항을 다시 풀고, 법규 숫자·기간 문항은 국가법령정보센터 원문과 대조해야 합니다.

## 6. 이 환경에서 확인하지 못한 것 → 수동 점검표

자동 테스트는 Chromium(크롬·엣지·삼성 인터넷과 같은 엔진)으로만 실행했습니다. 아래는 실제 기기에서 한 번씩 확인해 주세요.

| # | 환경 | 확인할 것 | 결과 |
|---|---|---|---|
| M-1 | iPhone Safari (WebKit) | 시험 1회 완주, 힌트, 글자 크기 '가+', 다크 모드 | ☐ |
| M-2 | iPhone | '홈 화면에 추가' → 아이콘으로 실행 → 비행기 모드에서 이어 풀기 (TC-18) | ☐ |
| M-3 | Android 삼성 인터넷 | 시험 1회 완주, 결과·오답노트 | ☐ |
| M-4 | PC 엣지 + 휴대폰 | PC에서 백업 파일 저장 → 휴대폰으로 옮겨 불러오기(합치기·덮어쓰기) (TC-13) | ☐ |
| M-5 | 크롬·사파리 시크릿 창 | 접속 시 '기록이 유지되지 않음' 안내, 창 닫았다 열면 기록 없음 (TC-17) | ☐ |
| M-6 | macOS Safari | 대시보드·시험·기록 그래프 표시 | ☐ |
| M-7 | 휴대폰 화면 읽기(TalkBack/VoiceOver) | 문제·보기·정답/오답 안내가 읽히는지 | ☐ |

> 같은 와이파이의 휴대폰에서는 PC에서 `실행.bat`을 켠 뒤 `http://PC의IP:8000`으로 접속합니다. 단, 오프라인·홈 화면 추가(M-2)는 보안 주소(https)에서만 동작하므로 7단계 GitHub Pages 배포 후 확인합니다.

## 7. 남은 일 (6단계 완료까지)

1. 수동 점검표 M-1~M-7 (M-2는 배포 후)
2. 사람 표본 검수 과목별 10% → 오류가 나오면 그 과목 전체 재검수
3. 문제 검수 진행: verified가 과목별 25/15/25/15 이상이 되면 실제 시험 가능
4. 베타 테스트(`docs/베타테스트_안내.md`) – 배포 주소가 생긴 뒤 5~10명
