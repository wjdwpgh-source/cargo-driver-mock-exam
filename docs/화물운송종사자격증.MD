## 1. 프로젝트 개요

### 1.1 목적
화물운송종사자격시험 응시자라면 **누구나, 언제든, 가입 없이** 접속하여 실제 출제 범위 기반의 모의고사를 풀고, 문제별 해설로 학습하며, 자신의 시험 결과와 오답을 확인·관리할 수 있는 **공개용 웹 프로그램**을 만든다.

### 1.2 배경
- 화물운송종사자격시험은 한국교통안전공단(TS)이 CBT 방식으로 시행한다.
- 응시자는 반복 풀이와 오답 확인으로 학습하는 경우가 많으나, 개인별 성적 이력과 오답을 체계적으로 관리하는 무료 도구는 부족하다.
- 문제를 데이터화하면 랜덤 출제, 과목별 학습, 오답 복습 등 다양한 학습 방식이 가능해진다.

### 1.3 운영 방식
- GitHub 저장소에 소스와 문제 데이터를 공개 등록한다.
- **GitHub Pages**로 무료 배포하여 별도 서버 없이 누구나 인터넷 주소로 접속하게 한다.
- 회원가입·로그인이 없으므로 개인정보를 수집하지 않는다.

### 1.4 실제 시험 기준 (출제 규격)

| 과목 | 문항 수 |
|---|---|
| 교통 및 화물자동차 운수사업 관련 법규 | 25 |
| 화물취급요령 | 15 |
| 안전운행 | 25 |
| 운송서비스 | 15 |
| **합계** | **80문항 / 80분** |

- 합격 기준: 100점 만점 기준 60점 이상 (48문항 이상 정답)
- 형식: 4지선다 객관식
- ※ 시험 규정은 개정될 수 있으므로 개발 시점에 한국교통안전공단 공지로 재확인한다.

- ~~회원가입 / 로그인 / 비밀번호~~ → 닉네임(ID) 방식으로 대체

## 3. 사용자 식별 및 기록 저장 방식

회원가입과 서버가 없으므로, 시험 기록은 **사용자 본인의 브라우저(로컬 저장소)**에 저장한다.

| 항목 | 내용 |
|---|---|
| ID 생성 | 첫 접속 시 닉네임 입력 (예: 홍길동, 화물왕) |
| 다중 ID | 같은 PC에서 여러 닉네임을 만들어 따로 기록 관리 가능 (가족·동료가 함께 사용) |
| 기록 위치 | 접속한 기기의 브라우저 내부 |
| 장점 | 가입 불필요, 개인정보 수집 없음, 서버 비용 0원 |

### 3.1 이 방식의 한계와 보완책
- **다른 기기에서는 기록이 보이지 않는다.** (PC에서 푼 기록이 휴대폰에는 없음)
- 브라우저 데이터 삭제·시크릿 모드 사용 시 기록이 사라진다.
- 보완: **기록 내보내기/가져오기**(백업 파일 저장 후 다른 기기에서 불러오기) 기능을 제공한다.

## 4. 기능 범위

### 4.1 필수 기능 (1차 개발, MVP)

**① 시작 / ID 선택**
- 닉네임 입력으로 새 ID 생성, 기존 ID 선택
- ID 이름 변경, ID 삭제

**② 문제 데이터**
- 지문, 보기 4개, 정답, 해설, 과목, 출처, 관련 법령, 난이도, 상태
- 이미지 포함 문제(표지판, 도표 등) 지원
- 문제 추가·수정은 GitHub 저장소의 데이터 파일 편집으로 처리
- `verified` 상태의 문제만 출제

**③ 모의시험 (실전 모드)**
- 과목별 규정 문항 수(25/15/25/15)로 랜덤 출제, 80분 타이머
- 답안 선택·변경, 문항 번호판으로 이동, 미응답 문항 표시
- 제출 시(또는 시간 종료 시) 자동 채점

**④ 채점 및 해설**
- 총점, 과목별 점수, 합격/불합격 판정
- 문제별 내 답 / 정답 / 해설 확인
- 헷갈린 문제는 '오답노트에 담기' 가능

**⑤ 성적 관리 (내 기록)**
- 응시 이력 목록 (일시, 점수, 합격 여부)
- 지난 시험 다시보기 (당시 답안과 해설 포함)
- 점수 추이 그래프, 과목별 평균 점수

**⑥ 시험 기록 초기화**
- 개별 시험 기록 삭제
- 현재 ID의 전체 기록 초기화
- 초기화 범위 선택: **실전 기록만 / 오답노트만 / 전체(실전 + 오답노트 + 복습 기록)**
- 실수 방지를 위한 확인 창 ("정말 초기화하시겠습니까?" → 확인 후 삭제)
- 초기화 전 백업 파일로 내보내기 권장 안내

**⑦ 기록 백업**
- 내 기록(응시 이력 + 오답노트 + 복습 기록)을 파일로 내보내기
- 백업 파일 불러오기

**⑧ 오답노트 및 복습 재시험**
- 상세 구조는 [4.3 오답노트·복습 구조](#43-오답노트복습-구조) 참고

### 4.2 추가 기능 (2차 이후 검토)
- 과목별 집중 학습 / 출처별 문제 풀이
- 북마크(즐겨찾기) 문제
- 취약 과목 분석 및 추천 문제
- 문제 오류 신고 (GitHub Issues 연결)

### 4.3 오답노트·복습 구조

#### (1) 전체 흐름
```
[실전 모의시험] ──제출·채점──▶ 틀린 문제·미응답 문제 자동 수집
                                        │
                                        ▼
                                  [오답노트]  ◀──── 복습에서 또 틀리면 횟수 누적
                                        │
                              복습 재시험 출제
                                        │
                     ┌──────────────────┴──────────────────┐
                 정답 처리                               오답 처리
                     │                                     │
          연속 정답 2회 달성 시                     연속 정답 0으로 초기화
          '복습 완료(졸업)' 이동                    틀린 횟수 +1
                     │
          이후 실전에서 다시 틀리면 오답노트로 재등록
```

#### (2) 오답 수집 규칙
| 항목 | 규칙 |
|---|---|
| 수집 대상 | 실전 모의시험에서 틀린 문제, 미응답 문제 |
| 수집 시점 | 시험 제출(채점) 즉시 자동 |
| 중복 처리 | 이미 오답노트에 있는 문제는 새로 추가하지 않고 틀린 횟수만 +1 |
| 수동 추가 | 맞힌 문제라도 헷갈린 문제는 결과·해설 화면에서 '오답노트에 담기' 가능 |
| 관리 단위 | 닉네임(ID)별로 따로 관리 |

#### (3) 복습 재시험 방식
| 항목 | 선택 옵션 |
|---|---|
| 출제 범위 | 전체 오답 / 과목별 / 많이 틀린 문제(틀린 횟수 2회 이상) / 최근 틀린 문제 |
| 문항 수 | 10 / 20 / 40 / 전체 |
| 풀이 방식 | **즉시 해설 모드**: 한 문제 풀 때마다 정답·해설 확인 (기본값) <br> **시험 모드**: 다 풀고 한 번에 채점 |
| 시간 제한 | 없음 (선택 시 문항당 1분 타이머) |
| 출제 순서 | 랜덤, 보기 순서도 섞어서 답 위치 암기 방지 |

※ 보기 순서를 섞더라도 채점과 기록은 **원래 보기 번호 기준**으로 저장한다.

#### (4) 복습 완료(졸업) 규칙
- 복습 재시험에서 **연속 2회 정답**이면 '복습 완료' 목록으로 이동한다.
- 복습 완료 문제는 기본 출제에서 빠지지만, 별도 메뉴에서 다시 풀 수 있다.
- 이후 실전 모의시험에서 다시 틀리면 오답노트로 재등록된다.
- 사용자가 직접 '복습 완료' 처리하거나 오답노트에서 제거할 수도 있다.

#### (5) 복습 기록과 실전 성적의 분리
- 복습 재시험 결과는 **실전 점수 추이·합격 통계에 포함하지 않는다.** (같은 문제를 반복해 점수가 부풀려지는 것을 방지)
- 복습 현황은 별도로 표시한다: 남은 오답 수, 과목별 오답 수, 복습 완료 수, 오답 감소 추이.

#### (6) 기타 규칙
- 문제가 `deprecated`(폐기) 상태로 바뀌면 오답노트에서 자동으로 숨긴다.
- 문제 내용이 수정된 경우(`version` 증가) 오답노트에 '수정된 문제' 표시를 한다.

## 5. 시스템 구성

### 5.1 구성도
```
[GitHub 저장소] ──자동 배포──▶ [GitHub Pages (공개 주소)]
                                       │
                                       ▼
                             [사용자 브라우저]
```

| 문제 데이터 | JSON 파일 (과목별 분리) |
| 기록 저장 | 브라우저 로컬 저장소(localStorage 또는 IndexedDB) |
| 그래프 | Chart.js 등 차트 라이브러리 |
| 배포 | GitHub Pages |
| 버전 관리 | Git / GitHub |

## 6. 데이터 구조 개요

### 6.1 문제 데이터 (GitHub 저장소, 공개)
| 항목 | 설명 |
|---|---|
| id | 문제 고유번호 |
| subject | 과목코드 |
| question | 지문 |
| choices | 보기 4개 |
| answer | 정답 번호 |
| explanation | 해설 |
| source | 출처 (자체 작성 / 공단 공개 자료 / 이용 허락 자료 등) |
| law_ref | 관련 법령 및 기준일 |
| difficulty | 난이도 |
| image | 이미지 경로 (선택) |
| status | 문제 상태 (draft / reviewed / verified / deprecated) |
| version | 문제 수정 버전 (내용 수정 시 +1) |
| updated_at | 최종 수정일 |

### 6.2 사용자 기록 (각자의 브라우저, 비공개)
| 항목 | 설명 |
|---|---|
| profiles | 닉네임 ID 목록 |
| exams | ID별 실전 응시 기록 (일시, 총점, 과목별 점수, 합격 여부) |
| answers | 응시별 문제번호와 선택 답 |
| wrong_notes | ID별 오답노트 (아래 표) |
| review_sessions | 복습 재시험 기록 (일시, 범위, 문항 수, 정답 수) – 실전 기록과 분리 저장 |

**wrong_notes (오답노트) 항목**
| 항목 | 설명 |
|---|---|
| question_id | 문제 고유번호 |
| question_version | 오답 등록 당시 문제 버전 ('수정된 문제' 표시용) |
| subject | 과목코드 (과목별 복습용) |
| wrong_count | 누적 틀린 횟수 |
| streak | 복습 연속 정답 횟수 (2 도달 시 졸업) |
| last_choice | 최근 내가 고른 답 (원래 보기 번호 기준) |
| first_wrong_at / last_wrong_at | 처음·최근 틀린 일시 |
| added_by | 등록 방식 (자동 / 수동) |
| state | active(복습 중) / mastered(복습 완료) |

## 7. 화면 구성 (안)

1. **시작 화면** – 시험 소개, 닉네임(ID) 입력/선택
2. **대시보드** – 최근 점수, 평균, 응시 횟수, 시험 시작 버튼, "복습할 오답 N문제" 바로가기
3. **시험 화면** – 문제, 보기, 타이머, 문항 번호판, 제출
4. **결과 화면** – 총점, 과목별 점수, 합격 여부
5. **해설 화면** – 문제별 내 답/정답/해설, '오답노트에 담기'
6. **내 기록 화면** – 응시 이력, 점수 추이 그래프, 기록 초기화, 백업/불러오기
7. **오답노트 화면** – 남은 오답 수, 과목별 오답 수, 오답 목록(틀린 횟수·최근 일시), 해설 보기, 제거·복습 완료 처리
8. **복습 재시험 화면** – 범위·문항 수·풀이 방식 선택 → 풀이(즉시 해설) → 복습 결과(졸업한 문제 표시)

## 8. 문제 데이터 구축 방안

### 8.1 데이터 확보 원칙
- 공개 배포이므로 **출제 범위(관련 법령, 화물취급·안전운행·운송서비스 기준)를 바탕으로 새로 작성한 문제**를 기본으로 한다.
- 문제 작성은 AI(Claude)가 초안을 만들고, 사람이 최신 법령·기준과 대조해 검수하는 방식으로 진행한다.
- 보조 자료로 한국교통안전공단 공개 자료, 이용 허락을 받은 자료를 활용할 수 있다.
- 해설은 관련 법령 조항과 핵심 개념 중심으로 작성한다.

> ⚠️ **저작권 유의사항 (공개 배포이므로 특히 중요)**
> 화물운송종사자격시험은 CBT 방식이라 공식 기출문제가 공개되지 않는 경우가 많다. 시중 교재나 유료 사이트의 문제·해설을 그대로 GitHub에 올리면 누구나 볼 수 있는 상태로 공개되어 저작권 침해 문제가 커질 수 있다. 공단 공개 자료, 직접 작성한 문제, 이용 허락을 받은 자료만 사용하고, 문제마다 출처를 기록한다.

### 8.2 용량 검토
| 항목 | 내용 |
|---|---|
| 문제 1개 용량 | 해설 포함 약 1~2KB (JSON) |
| 1,200문항 | 약 1.2~2.4MB |
| GitHub Pages 한도 | 사이트 1GB, 파일 1개 100MB |
| 결론 | 텍스트 문제는 용량 제약 없음. 이미지는 WebP 등으로 압축해 사용 |

### 8.3 문제 수량 목표
실전 시험 80문항 대비 3배 이상의 문제 풀을 확보해 반복 출제를 줄인다. 과목별 수량은 실제 출제 비율(25:15:25:15)을 따른다.

| 단계 | 총 문항 | 법규 | 화물취급요령 | 안전운행 | 운송서비스 | 기준 |
|---|---|---|---|---|---|---|
| 1차 (MVP 공개) | 400 | 125 | 75 | 125 | 75 | 실전 5회 응시 시 중복 최소 |
| 2차 (확장) | 800 | 250 | 150 | 250 | 150 | 실전 10회 수준 |
| 최종 목표 | 1,200 이상 | 375 | 225 | 375 | 225 | 실전 15회 수준 |

### 8.4 문제 작성 및 검수 절차
```
① 초안 작성 → ② 1차 검수(정답·해설) → ③ 법령 대조 검수 → ④ 등록(공개) → ⑤ 오류 신고 반영·정기 점검
```

| 단계 | 내용 |
|---|---|
| ① 초안 작성 | 과목별로 1회 30~50문항씩 작성 (지문, 보기 4개, 정답, 해설, 관련 법령) |
| ② 1차 검수 | 정답이 하나뿐인지, 보기가 명확한지, 해설이 정답 근거를 설명하는지 확인 |
| ③ 법령 대조 | 법규 과목의 수치(벌칙·과태료 금액, 기간, 기준)를 국가법령정보센터 최신 조문과 대조 |
| ④ 등록 | 엑셀 → JSON 변환 후 GitHub 저장소에 반영 |
| ⑤ 사후 관리 | GitHub Issues 오류 신고 처리, 법령 개정 시 해당 문제 수정(`version` 증가) 또는 폐기 |

### 8.5 문제 상태 관리
문제 데이터에 상태 항목을 두어 검수를 마친 문제만 시험에 출제한다.

| 상태 | 의미 | 출제 여부 |
|---|---|---|
| draft | 초안 작성 완료 | 출제 안 함 |
| reviewed | 1차 검수 완료 | 출제 안 함 |
| verified | 법령 대조까지 완료 | **출제** |
| deprecated | 법령 개정 등으로 폐기 | 출제 안 함 (오답노트에서도 숨김) |

### 8.6 작업 일정 (안)
| 구분 | 내용 |
|---|---|
| 1회 작업량 | 과목 1개, 30~50문항 |
| 1차 400문항 | 약 10회 작업 + 검수 |
| 우선순위 | 비중이 큰 법규·안전운행부터 작성 |

## 12. PRD 단계에서 결정할 사항

### 12.1 미결정 사항
1. 1차 개발에 추가로 포함할 기능 범위 (북마크, 취약 과목 분석 등)
2. 저장소 이름과 공개 라이선스 종류
3. 화면 디자인 방향 (모바일 우선 여부)
4. 문제 오류 신고 방식
5. 문제 입력용 엑셀 양식 확정

### 12.2 결정 완료 사항
- 사용 범위: 인터넷 공개 서비스 (GitHub Pages, 정적 웹사이트)
- 사용자 식별: 회원가입 없이 닉네임(ID) + 브라우저 저장
- 관리자 기능: 별도 화면 없음, 저장소 데이터 파일 직접 수정
- 초기 문제 수량: 1차 400문항 → 2차 800문항 → 최종 1,200문항 이상 (8.3 참고)
- 데이터 확보 경로: 출제 범위 기반 신규 작성 + 검수 (8.1 참고)
- 오답노트·복습 재시험: 1차 개발(MVP)에 포함 (4.3 참고)
